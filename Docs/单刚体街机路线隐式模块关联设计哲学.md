# 单刚体街机路线的隐式模块关联设计哲学

> [!IMPORTANT]
> 在**解析力模型**（Analytical Force Model）的**单刚体**（Single Rigid Body）模拟路线下，街机模式的载具仅需一个**底盘**（Chassis）、一个**变速箱**（Transmission）、一个**离合器**（Clutch）、一个**轮轴**（Axle）、一个**引擎**（Engine），其余模块不限数量；在此约束下，模块间的组织关系由**显式引用**（Explicit Reference）转为**隐式关联**（Implicit Association），由模块类型确定性推导，是更清晰、简洁且高效的架构选择。

---

## 一、背景与适用范围

### 1. 技术前提

本哲学建立在以下已被源码验证的机制事实之上（参见《ChaosVehicles 模拟树单刚体动力链机制分析》）：

- `ChaosVehicles` 的**模拟树**（Simulation Tree，`FSimModuleTree`）对任何模块类型均无数量约束，扭矩沿树的**父子边**（Parent-Child Edge）由 `TransmitTorque()` 传递；
- `Simulate()` 的入口签名限定单一**根粒子**（Root Particle），一棵树等价于一个刚体、一辆载具；
- 动力链连接关系完全由树结构定义，与模块实例数量无关。

### 2. 适用范围

- **解析力模型**：所有子系统以简化公式计算力，汇入延迟力容器，由底层求解器统一积分；
- **单刚体路线**：载具整体对应一个物理刚体，车轮与动力系统为模拟内部的一维积分子系统，不是独立刚体；
- **街机模式**：追求手感稳定与行为可预期，不需要多套独立动力总成（多引擎混动、多桥独立驱动等）的物理表达。

不适用范围：需要多套动力链独立控制的模拟（如双引擎坦克的差速转向）、一树多载具的聚合模拟。此类需求下隐式关联无法表达拓扑意图，显式配置是必要的。

## 二、约束模型

### 1. 单例槽位

| 模块类型 | 数量约束 | 树内角色 |
|---|---|---|
| **底盘**（Chassis） | 1 | 树根，施加拖拽力与角阻尼 |
| **引擎**（Engine） | 1 | **原动机**（Prime Mover），查曲线输出扭矩 |
| **离合器**（Clutch） | 1 | 引擎与变速箱之间的转速耦合节点 |
| **变速箱**（Transmission） | 1 | 挡位状态机与齿比变换 |
| **轮轴**（Axle） | 1 | 带惯性的扭矩中继节点 |
| **车轮**（Wheel） | 不限 | 扭矩最末端的消费节点 |
| **悬挂**（Suspension） | 不限 | 弹簧-阻尼力产出节点 |
| **电机**（Motor） | 不限 | 原动机的替代形态 |
| **翼面**（Aerofoil）、**推进器**（Thruster）等 | 不限 | 辅助力源 |

### 2. 规范拓扑

单动力链的规范形态为：

```
底盘 → 原动机 → 离合器 → 变速箱 → 轮轴 → 车轮 × N
                                        悬挂 × N（挂配对车轮之下）
辅助模块 × N（挂底盘之下）
```

该拓扑是**单例约束**（Singleton Constraint）下的唯一范式：链上每一环至多一个实例，全部车轮共享单链输出的扭矩（均分**开式差速**，Open Differential）。

## 三、显式转隐式的论证

### 1. 显式引用的成本

在多动力链需求下，模块间关系必须由用户配置的显式引用（如"引擎→离合器""车轮→轮轴"的单向引用字段）声明。其成本为：

- **配置负担**：每个动力链模块需要逐一配置上下游引用，引用数量随模块数量线性增长；
- **错误状态空间**：引用缺失、指向已销毁组件、形成环路、拓扑歧义（多个模块引用同一目标）等各类失效模式均需独立处理；
- **兜底路径膨胀**：缺失引用的模块不能静默丢弃，需要"按首个上游接管并告警"一类的兜底逻辑，兜底本身成为需要测试与维护的代码路径；
- **验证成本**：任何拓扑变更（部件增删、运行时变形）后，全部引用的解析结果都需要重新校验。

### 2. 隐式关联的依据

单例约束成立时，上述成本失去存在必要：

- **拓扑唯一性**：底盘、引擎、离合、变速箱、轮轴各只有一个实例时，"哪个引擎接哪个离合器"不存在歧义——只有一种合法连接方式；
- **确定性推导**（Deterministic Derivation）：整棵树的父子关系可以由模块类型集合经固定规则推导得出，无需任何用户输入；
- **规则封闭**：隐式规则的数量固定（单例槽位序、缺项回退、按驱动组件配对），不随模块数量增长。

### 3. 收益

**清晰**：树结构存在唯一规范形态，用户无需理解引用语义即可预测模块的树内位置；阅读配置时不存在"引用了什么、漏配了什么"的心智负担。

**简洁**：模块组件上不存在引用字段，配置面板仅保留物理参数；构建代码中不存在引用解析、反向查找与兜底接管路径；单次遍历分类即可完成全部模块的分拣。

**高效**：确定性推导使得"模块集合一致即整棵树一致"成立，幂等判定只需校验集合本身（数量、驱动组件、粒子索引、动画开关），无需比对派生关系；重复的拓扑变更信号可以被精确跳过，避免逐帧销毁重建引起的模拟状态抖动。

## 四、隐式关联规则

### 1. 单例槽位序

```
槽位顺序：底盘 → 原动机 → 离合器 → 变速箱 → 轮轴
```

- 每个槽位取该类型的首个实例（按固定收集顺序：快照实体优先，其后为宿主上的组件）；
- 多余的单例实例不入树，聚合告警提示配置冗余；
- **原动机槽**由首个引擎占据；无引擎时由首个**电机**（Motor）顶替，其余电机归入辅助模块挂到底盘之下。电机作为原动机的替代形态保留驱动能力，不因隐式化而失效。

### 2. 缺项回退

链上某一环缺失时，下游模块挂到**最近的现存上游**：

```
离合器父节点   = 原动机（缺则底盘）
变速箱父节点   = 离合器（缺则原动机，再缺则底盘）
轮轴父节点     = 变速箱（缺则离合器 → 原动机 → 底盘）
车轮父节点     = 轮轴（缺则变速箱 → 离合器 → 原动机 → 底盘）
```

回退链与槽位序方向一致，规则闭合。仅有底盘与车轮的载具（无动力链）退化为非驱动轮载具，仍然可模拟。

### 3. 悬挂配对

悬挂挂到与其共用**驱动组件**（Driven Component）的车轮之下。该规则的依据：车轮与悬挂在物理上属于同一部件（车轮网格体），二者引用同一物理组件是自然的工作流。配对失败（悬挂无驱动组件或无共享车轮）时挂到底盘之下并告警——此时车轮失去悬挂力，属于必须显式暴露的配置错误。

### 4. 悬挂作为车轮子节点的执行序依据

悬挂位于配对车轮之下，使**叶先序**（Leaf-First）遍历时悬挂先于车轮求解，车轮在同一物理步内即可消费到最新的悬挂法向力。

## 五、边界条件与失效模式

| 场景 | 处理 | 依据 |
|---|---|---|
| 单例类型存在多个实例 | 首个入树，其余忽略并告警 | 拓扑唯一性不因冗余配置而破坏 |
| 无有效底盘 | 清除全部模块（载具解体） | 底盘是树根与刚体锚点，缺失即载具不存在 |
| 底盘驱动组件离开集群 | 该底盘视为无效，取下一个有效底盘 | 离簇底盘的粒子索引已失效 |
| 悬挂配对失败 | 挂底盘并告警 | 车轮失去悬挂力是不可静默的功能损失 |
| 原动机模块创建失败 | 下游经缺项回退继续入树 | 单点失败不阻断整棵树 |
| 底盘模块创建失败 | 清除全部模块 | 后续节点将以无效父索引入树，破坏遍历序 |
| 空模块集合（解体后重组） | 先固化积分状态再清除，重组后回填 | 车轮转角、挡位等积分量不随几何重算 |

## 六、与显式配置的决策判据

隐式关联的适用性可由一个判据决定：**拓扑是否存在唯一合法形态**。

- 单例约束成立时，动力链各槽位至多一个实例，拓扑唯一，隐式推导与用户意图必然一致——隐式优于显式；
- 单例约束不成立时（多引擎、多轮轴独立驱动），同一模块集合可对应多种合法拓扑，隐式推导无法代表用户意图——必须退回显式配置。

换言之，显式引用的成本只有在"拓扑存在歧义"时才是必要开销；约束一旦收紧，显式配置退化为徒增复杂度的冗余仪式，此时将其替换为确定性推导规则，即同时获得清晰性、简洁性与效率。
